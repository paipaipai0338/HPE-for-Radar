# P4JointMemory：坐标解码前的空间证据与关节记忆

已完成 40 轮训练，最佳为第 37 轮：同帧 MPJPE 12.9256 cm。当前最佳联合微调模型为 12.8436 cm，见 [P4JointFineTune.md](P4JointFineTune.md)。

编码器与解码器的第二阶段联合微调已实现，启动与缓存说明见 [P4JointFineTune.md](P4JointFineTune.md)。原冻结编码器训练入口继续保留作为对照。

实验 `20261102_164747` 的固定权重消融：固定 epoch 30 的全量推理消融见 `experiments/P4JointMemory/20261102_164747/ablation_epoch30_20261102_175838/analysis.md`；完整模型 12.9516 cm，清空额外历史 13.3063 cm，去掉记忆特征更新 13.2468 cm，去掉关节 ID 查询 12.9521 cm。空间证据与历史有用，但逐关节分工很弱，方向反向帧仅从 P4 的 1690 降到 1685。此处为固定权重推理干预，不是分别重训练的结构比较。

## 为什么调整

同帧 P4 对照为 13.3004 cm。近水平姿态和头脚反向是主要高误差来源；基线验证集近水平姿态约占 12.34%，误差约 26.29 cm。仅降低少数反向帧仍不足以达到整体 10 cm。

原 P4 在 Transformer 后把每帧空间 token 最大池化成一个 128 维向量，再一次性输出 17 个关节。池化后可用的空间对应关系变少；坐标后处理只能依据已压缩的观测作修正。新的可检验假设是：在压缩为坐标之前，为每个关节保留当前空间证据与长期语义状态，比继续在最终骨架上加翻转规则更有价值。冻结编码器可能仍限制收益，需要用完整验证来判断。

## 模型

```text
原 FFTGen 点云 → 原 P4 编码器（冻结，16 帧输入）
                         ├─ 每帧约 50×128 空间 token + 对应锚点 XYZ
                         └─ 原 128 维池化特征
                                      ↓
17 个关节查询（关节 ID + 当前全局特征 + 历史关节状态）
      → 对空间 token 做交叉注意力
      → 共享 GRUCell 更新 17 个独立的 64 维关节状态
      → 当前全局特征 + 关节状态的特征更新
      → 迁移的 P4 输出头 → high 坐标关节 → 标定变换为 low 坐标
```

新解码器 205475 个可训练参数；其中 46387 来自原 P4 输出头，其余 159088 为新增参数。原 P4 总参数 311987；移除原输出头后与新解码器组成的推理网络共 471075 个参数。缓存训练只训练新解码器，输出头用较低学习率。特征更新层零初始化，开始时近似原 P4 输出；缓存与解码的 BF16/FP32 差异会产生小的数值偏差，epoch 0 单独报告，不能宣称逐位复现。

输入为 token、锚点 XYZ、池化特征、质量特征、标定变换；原粗骨架只用于指标对照，GT 只用于监督与离线裁剪/轨迹关联。没有骨架翻转候选或推理方向阈值。每个人独立状态；片段切换、歧义交叉、时间间隔 >0.25 s 时重置；跨训练块保留数值并截断梯度。无有效 token 时保持状态与先前上下文，冷启动无观测输出零。该缺测保持假定同一片段标定固定。

## 数据和训练

复用指定 P4 实验的配置及检查点，不修改原数据处理：FFTGen、T=16、acc_frame=3、200 点、原划分、原 high 坐标输入和不中心化设置，输出与监督统一到 low 坐标。每个有效窗口只取末帧，连续去重计分。仍要求窗口内观测与身份有效，真实全缺测窗口尚未纳入，只通过解码器遮挡增强探测鲁棒性。该流程依赖 GT 裁剪和关联，属于离线姿态评估，不等于已具备部署所需的检测跟踪。

训练为非重叠 128 帧轨迹块、batch 16、最长 40 轮、patience 10；随机遮掉 20% token，并以 0.3 概率插入最长 64 帧全缺测段。遮挡仅作用于解码器证据，部分 token 遮挡时仍保留原全局特征，不等同于原始点云缺失增强。验证不加噪声，不使用未来帧。默认 MPJPE 对 GT 近水平姿态加权 2 倍，另加 0.02 倍头脚方向余弦损失；这些 GT 几何量仅用于训练损失和审计。

配置在 `run/p4_joint_memory.yaml`，默认 `cuda:1`；模型维度在 `models/P4JointMemory/model_config.yaml`。

```bash
conda activate pytorch
# 正式运行会自动提取空间证据并训练
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 python -m run.train_p4_joint_memory
# 可选：仅完成证据提取
python -m run.train_p4_joint_memory --prepare-only
# 小规模工程检查，不代表精度
python -m run.train_p4_joint_memory --smoke
```

首次需要重新提取空间证据，原 pooled-feature 缓存无法恢复空间 token。新缓存位于 `outputs/p4_joint_memory/cache`，按组原子保存和复用；全量预计约 12 GB，训练时会载入 CPU 内存。不要同时运行共享该缓存的两个提取任务。首次提取仍需原 P4 的 CPU 数据预处理与 GPU 推理；缓存完成后训练不再逐轮加载原始点云。

输出 `experiments/P4JointMemory/<时间戳>/`，含 best/last 权重、配置、模型源码、证据清单、history。epoch 0 也可成为最佳结果；用 `all.decoded.mpjpe` 选择最佳，不丢弃冷启动帧。warm/cold、根误差、相对误差、每组指标和头脚反向统计同步记录。

```bash
python -m run.analyze_pose_refiner --experiment experiments/P4JointMemory/<时间戳> --checkpoint best.pth --device cuda:1
```

诊断 JSON 为 `diagnosis_best.json`，新模型的解码结果沿用历史字段名 `refined`。应同时检查近水平组、静态持续段、introduced_opposite 与起身响应，不能只看总体均值。若仅训练集变好，应优先核查语义分支是否过拟合与数据域差异，再决定是否解冻前级；不要直接增加后处理规则。

## 已验证与边界

工程冒烟验证：训练与验证各首组 128 个窗口，完成空间 token 缓存、一次 GPU 更新及验证。少量样本不包含近水平帧，不能支持头脚反向改善结论。单元测试覆盖迁移输出头、标定旋转、因果与分块一致性、缺测、空间证据敏感性、点序不变性、轨迹切换和诊断快照加载。

完整训练仍未达到 10 cm 目标。冻结编码器阶段使用已在训练集拟合过的前级，不解决数据标注错位、坐标标定错误或未观测关节不可辨识问题。


## 2026-11-04：可学习的观测更新门控

`models/P4JointMemory/model_config.yaml` 默认开启 `reliability_gating`。全局上下文按“当前特征与历史之差 + 6维质量”学习逐通道更新力度；各关节按“空间证据 + 自身历史 + 质量编码”学习独立更新力度。低质量观测可以减少更新，全局特征不再无条件覆盖历史。缺测仍保持状态，首次有效观测直接初始化，避免保留零状态。这里没有硬编码点数阈值，也没有显式拆出世界位置和头脚朝向状态。

质量仍沿用当前点数、积累点数、速度均值/最大值、点云范围、时间间隔，尚未添加真实TLV动态点计数；保持原缓存格式和16帧、acc_frame=3的数据处理。关节门控可以独立学习，但是否形成部位分工需训练后验证。门控末层零权重、bias=2，初始允许大部分观测更新。

新训练使用 `python -m run.train_p4_joint_memory`，默认 cuda:1。复用可用的空间证据缓存；数据划分或源数据变化仍按原指纹机制处理。此入口从原P4输出头初始化新解码器，不能称为从旧最佳记忆模型继续微调。旧实验源码快照和权重不变。若之后联合微调，需要将 `run/p4_joint_finetune.yaml` 的 `init_experiment` 指向此次新实验；现有默认值仍对应旧结构。

新增测试检查低增益下保持上下文与关节状态、因果分块一致性，以及两类门控的有效梯度。相关19项回归通过；未启动正式训练，不宣称已经改善精度。
