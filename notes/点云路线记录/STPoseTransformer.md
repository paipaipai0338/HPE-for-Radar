# HoloSense 模型结构迁移

来源：`HoloSense/runs/spatial_cross_temporal_parallel/20260427_1523`。

实验目录只保存了配置和权重，没有源码快照。迁移依据为 `config_resolved.json`、
`best.pt` 和相邻历史版本 `8578485` 中关闭 register tokens、关闭因果 mask 的路径。
该权重的速度门控参数为 1.3029158，确认其参与了训练；HoloSense 当前源码已将
速度门控和按速度选点注释，不能直接复制当前版本作为该实验模型。

## 模型

`models/STPoseTransformer/STPoseTransformer.py` 自包含模型及所需点云操作，
通过现有 `build_model` 注册；无需依赖 HoloSense 的代码或新增安装包。

流程：

1. 输入点云使用 XYZ 和径向速度，共 4 列，其余列忽略。
2. 模型直接使用输入的低位机 XYZ 坐标，不做首帧或逐帧中心化。
3. 点 MLP、速度软门控和空间位置编码；每帧按速度幅值选点，上限由 `spatial_max_points` 控制。
4. 在低位机绝对坐标范围 X=[0,6]、Y=[-3,3]、Z=[-2,2] 内进行 0.1、0.2、0.4 m 三尺度体素最大池化，残差写回点特征。
5. 每关节一个可学习查询，交叉注意力读取点特征。
6. 每关节特征压缩为 12 维，拼接后进入两层非因果时间 Transformer。
7. 直接回归低位机坐标系下的姿态，输出 `pose: [B,T,1,17,3]`。

原实验为 23 关节、时间特征宽度 276；迁移后为 COCO 17 关节、时间特征宽度 204。
基础结构参数来自原实验；当前配置已取消原模型首帧中心化，并调整选点数与体素范围，以同目录 `model_config.yaml` 为准。
体素池化使用以点数为上限的分组缓冲，与原实现的输出和梯度等价，不分配场景大小的稠密空网格。

## 当前训练设置

沿用本工程 FFTGen 点云、低位机坐标、GT 框裁剪、每人每帧 200 点、
16 帧窗口、前 3 帧点云累积、既有数据划分和增强。
原实验内部选取 92 点，当前配置为 128 点；Dataset 的每人每帧重采样仍为 200 点。
数据处理和训练循环无需特殊分支，损失仍为当前配置的 Positive MPJPE。

从头训练，使用本工程统一初始化；没有加载 HoloSense 的 23 关节权重。
原实验的损失权重、优化器参数、数据增强和人员划分均不迁入。
P4 当前使用 XYZ 加两个额外特征，本模型按原实验只用 XYZV，比较结果需注明此差异。

在项目根目录启动：

```bash
python -m run.main --config run/config.yaml
```

当前配置的实验输出位于本工程 `experiments/STPoseTransformer/<时间戳>/`。
独立回归检查：

```bash
python -m unittest models.STPoseTransformer.test_st_pose_transformer
```

- 上述原模型数值对照针对取消中心化之前的迁移版本；当前绝对坐标版本与原实验前向含义不同。
- 占用体素池化对照原稠密/稀疏实现，输出与梯度一致。
- 回归检查覆盖 FP32/BF16 前反向、空帧/空序列、绝对坐标输入输出、无效点 mask、
  现有逐人训练和连续片段验证，以及保存后的模型源码独立加载。
- 真实 FFTGen 组 `20260703/group_011` 以现有 16 帧、acc_frame=3、低位机坐标
  处理后通过 CPU BF16 单批训练和验证检查。CPU BF16 检查关闭 oneDNN，使用原生内核。
  后续性能优化还通过了真实 CUDA 单批训练、验证及连续批次吞吐检查；未启动完整收敛实验。
- 实验没有保存原始源码，数值一致性针对上述相邻历史参考路径；不能证明未归档代码的所有行为。

## 点云前处理性能优化

`run/utils/process_one_epoch.py` 将原有坐标与增广变换合成为一次仿射变换，
由训练、验证及导出入口传入目标 device，在 GPU 上执行。
逐人逐帧采样改为批量操作：训练时点足够则不放回抽样，不足则保留全部有效点后补点并打乱；
验证时仍按原始点顺序等间隔取点或循环补点；空帧保持零和无效 mask。
16 帧、3 帧累积、200 点、128 点模型内筛选、数据划分及损失设置均未调整。

取消模型中心化之前，RTX 5090、BF16、batch=64、8 个 worker，在真实组 `20260703/group_011` 上对照：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 坐标转换（含 GPU 传输） | 251 ms | 7.6 ms |
| 裁剪及重采样 | 162 ms | 1.5 ms |
| 采样中的 CUDA 同步次数/批 | 1024 | 0 |
| 连续训练稳定吞吐 | 2.28 batch/s | 27.42 batch/s |

连续吞吐各测 15 批，统计排除最初两批与末尾不足 64 的批次，约提升 12 倍。
结果针对一个 SSD 单人组；全量随机读取、多人组及其他 GPU 任务会影响绝对速度。
原、新路径在真实批次的验证输入和 GT 一致性检查通过，容差为 `4e-6`。
训练采样规则相同，但随机数消费顺序改变，相同 seed 不再逐点复现旧实现。

```bash
python -m unittest run.utils.test_pointcloud_processing models.STPoseTransformer.test_st_pose_transformer
```

后续同步优化：体素池化用固定长度排序及 scatter 聚合代替动态布尔索引和 unique；
无效点各占独立临时组，避免原子操作集中争用。分组指标在 GPU 汇总后一次回传，
保留原始低位机 GT 定义的椭圆区域和全部计数。模型内部前后向同步由 34 次降至 10 次，
真实批次整网验证输出最大差异为 0；loss 及全部分组统计与旧路径一致。
CUDA 检查覆盖 FP32/BF16、最大值并列梯度、无效点、范围外点及空帧。

本轮同次 12 批对照（排除最初两批，batch=64）：20.65 → 29.59 batch/s，约再提升 43%。
机器上有其他 GPU 任务，绝对速度与上轮测试不能直接比较。
固定长度分组缓冲增加显存，本轮单人批次 PyTorch 分配峰值约为 1.25 GiB。

当前总参数和可训练参数均为 729,916（约 0.73M），其中时间编码器 670,344（91.8%）。
纯 FP32 参数约 2.78 MiB；训练显存主要来自激活和点云分组缓冲。
内部选点数、体素范围的调整不改变参数量。

当前取消中心化后，旧模型参数仍可按形状加载，但其输入输出含义已经改变；旧实验结果与该版本需分别记录。
