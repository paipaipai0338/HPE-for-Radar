# 骨架框选与 ONNX 姿态推理：Qt 交付说明

本文可独立交付，无需访问训练工程。包含两个主题：①根据骨架生成三维包围盒并筛选点云；②使用已转换的 ONNX 模型完成姿态推理及后处理。

本文描述参考实现的行为。ONNX 已完成转换；Qt 实际数值一致性仍需用相同输入进行验收。

## 交付接口与参数

交付包需包含 ONNX 文件、对应预处理参数、相机到高/低位雷达外参，以及一组输入输出参考数据。接收方应核对 ONNX 输入输出元数据，避免配置与模型不匹配。

| 参数 | 本文参考值 | 说明 |
|---|---|---|
| 时间窗口 T | 16 | ONNX 中固定 |
| 每人每帧点数 M | 200 | ONNX 中固定 |
| 额外历史帧数 H | 3 | 当前帧加前三帧，共最多4帧 |
| 骨架关节数 | 17 | 关节顺序见下表 |
| 包围盒外扩 | 0.30 m | 每个面向外扩展 |
| 最少框内点数 | 10 | 积累、裁剪后，重采样前统计 |
| 框选及模型坐标系 | high | 也支持配套配置为low，不能自行更改 |
| 中心化 | 关闭 | 可选XYZ中心化，或low下仅XY中心化 |
| 参考人数上限 | 4 | ONNX人数batch动态；参考预处理保留前4个槽位 |
| 推理增广 | 关闭 | 不加随机旋转、高度扰动或点丢弃 |

以上数值需与实际交付模型及配套配置确认，不能仅修改 T、M 后继续使用固定尺寸的 ONNX。

每个原始帧提供：

- 帧序号、采集时间戳（秒）；按采集顺序处理，空帧保留位置。
- 高位雷达点云 `[n,6]`：`[x,y,z,f0,f1,tag]`。XYZ单位为米；f0、f1直接保留上游数值，不自行归一化。
- 同步的参考骨架 `[P,17,3]` 及对应人员ID。骨架初始坐标系必须明确。
- 人员ID需在时间窗口内保持一致。参考实现按骨架数组槽位作为ID，并不包含跟踪器；换人或ID重用时应重置历史。

骨架索引：

| 索引 | 关节 | 索引 | 关节 |
|---:|---|---:|---|
| 0 | 鼻 | 9 | 左腕 |
| 1 | 左眼 | 10 | 右腕 |
| 2 | 右眼 | 11 | 左髋 |
| 3 | 左耳 | 12 | 右髋 |
| 4 | 右耳 | 13 | 左膝 |
| 5 | 左肩 | 14 | 右膝 |
| 6 | 右肩 | 15 | 左踝 |
| 7 | 左肘 | 16 | 右踝 |
| 8 | 右肘 | — | — |

本流程依赖上游骨架生成框，不是仅输入整场点云即可自动检测人体。若改用检测框，应另行验证框、ID及姿态效果，不能视为与骨架框输入等价。

# 主题一：骨架生成包围盒与点云框选

## 1. 统一骨架与点云坐标系

high、low分别表示高位、低位雷达坐标系。以下公式使用列向量，R为3×3旋转矩阵，t为3维平移向量。

相机骨架转换到雷达坐标系：

```text
s_high = R_high × s_camera + t_high
s_low  = R_low  × s_camera + t_low
```

两套外参均从同一个相机坐标系出发，可推导：

```text
R_hl = R_low × R_highᵀ
t_hl = t_low - R_hl × t_high
p_low = R_hl × p_high + t_hl
p_high = R_hlᵀ × (p_low - t_hl)
```

若使用行向量存储，正向转换写为 `p_low = p_high × R_hlᵀ + t_hl`。矩阵内存的行/列主序与数学上是否转置是两件事，应使用已知坐标点验证。

骨架与雷达帧需时间对齐。参考文件流程选择采集时间最近的骨架，未设置最大时间差。接入其他同步方式时，应保证对比使用同一帧骨架。

最终在high框选，就把骨架与点云都放到high；在low框选，就先同步转到low，再计算包围盒。低位下重新求轴对齐框，通常不等价于高位框选后仅旋转选中点。

**训练背景说明：高度增广在原始low坐标下执行 `z -= delta_height`，随后转回high进行角度增广，最后转换到选定坐标系并重新生成框。Qt正常推理关闭这些随机增广。**

## 2. 每人每帧计算三维包围盒

设一个人的17个关节点为 `s[j]`，分别对XYZ取极值：

```text
minXYZ = 各轴的17点最小值 - (0.30,0.30,0.30)
maxXYZ = 各轴的17点最大值 + (0.30,0.30,0.30)
bbox   = [xmin,ymin,zmin,xmax,ymax,zmax]
```

这是轴对齐长方体，不计算点到骨骼的距离，不使用骨骼连线或髋中心生成框。每轴总尺寸增加0.60米。

例如骨架范围为：

```text
X：[2.0,2.4]，Y：[-0.3,0.3]，Z：[-0.8,0.9]
```

生成的框为：

```text
[1.7,-0.6,-1.1, 2.7,0.6,1.2]
```

交付输入应保证骨架坐标有限；含NaN/Inf时不能直接生成可用框。有限但异常的关节点也会拉大包围盒，应在上游解决，不在此步骤擅自改变极值规则。

## 3. 点云先积累，再框选

先将点云转换为float32，删除任一列含NaN/Inf的整行，保持剩余点的原始顺序。读取失败或无有效点时保留为空帧。

每个时间位置i的候选点云为：

```text
A[i] = concatenate(P[max(0,i-H)], ..., P[i])
```

拼接从旧帧到新帧，每帧内部点序不变。组开始历史不足时只用已有帧。不去重、不做运动补偿，也不只积累静态点。

用**当前时间位置i的骨架框**筛选整个A[i]，不是各历史帧先按各自骨架裁剪再拼接。

保留条件：

```text
xmin <= x <= xmax
且 ymin <= y <= ymax
且 zmin <= z <= zmax
```

边界点保留。只检查XYZ，其余三列随点保留。两个框重叠时，一个点可以进入两个人的输入，不做独占归属。框内背景点也会保留。

## 4. 单帧观测质量单独统计

后处理还需要每人当前帧的两个计数。使用**高位坐标下当前骨架生成的框**，对**当前原始点云P[i]**统计：

```text
D = 框内动态点数：abs(tag-1.0) <= 1e-8 + 1e-5
N = 框内全部点数
```

不能用积累后的点数或固定采样后的200点代替D、N。这两个计数与模型的“裁剪后至少10点”是不同条件。

原始当前帧为空时D=N=0，但历史积累仍可能使模型输入达到10点。

# 主题二：Qt端ONNX推理与输出处理

## 5. Qt与ONNX的职责边界

| Qt负责（图外） | ONNX已包含（图内） |
|---|---|
| 时间同步、坐标转换、点云清理 | 按mask处理无效点 |
| 历史积累、滑窗、骨架框选 | FPS、邻域查询、点特征聚合 |
| 点数门槛、中心化、固定点数采样 | P4DConv、位置编码、Transformer |
| 完整窗口筛选、人员ID映射 | 姿态头，输出窗口内全部T帧骨架 |
| 连续五列输入打包与模型调用 | 不包含左列图外步骤 |
| 加回中心、坐标还原、取末帧 | — |
| 时序后处理、缓存与显示 | — |

Qt无需重写FPS、邻域查询或网络层。参考ONNX已将这些步骤转换成标准算子，opset为17。Qt只需加载已交付模型，按接口准备数据并调用推理后端。

## 6. 滑窗与单人输入准备

### 6.1 时间窗口

先按整段数据生成积累点云A，再构建步长为1、长度为T的滑窗：

```text
窗口s：[A[s], A[s+1], ..., A[s+T-1]]
输出对应帧：s+T-1
```

窗口左端不能清空历史。例如s=10、H=3，A[10]仍包含P[7]～P[10]。

T=16时最早输出为帧15（从0计数）。前15帧不复制首帧补窗口；整段少于16帧时无输出。一个中间窗口最多依赖19个原始帧，但网络时间维仍为16。

### 6.2 每人每帧的处理顺序

1. 在模型配置坐标系内，使用该时间位置的骨架框裁剪积累点云。
2. 裁剪后少于10点，则该人该时间位置无效。
3. 按配套配置中心化，保存中心c；未启用时c为零。
4. 将有效点确定性采样到M点。
5. 只有同一个人的T个时间位置全部有效，才将此人加入本次模型batch。

中心化规则：

- XYZ中心化：c为框内点云XYZ均值。
- low下XY中心化：c为框内点云XY均值，`c.z=0`。
- 点云XYZ减去c，f0、f1不变。c不是骨架髋中心或框中心。

固定点数采样，设裁剪后有效点数为count：

```text
count >= M：在[0,count-1]上取M个等间距浮点索引，再向零截断为整数
0 < count < M：index[k] = k % count，k=0,...,M-1
```

保留有效点的原始顺序，不排序、不随机、不用体素或FPS代替。索引边界以参考输入为准，不能改成四舍五入。参考推理不做随机点丢弃，因此有效窗口的采样mask全真。

只保留有效人员后必须记录原ID映射。例如原ID为1、3时，模型batch索引虽然是0、1，输出仍对应ID 1、3。

## 7. ONNX接口和内存布局

| 名称 | 方向 | 类型 | 形状（参考值） |
|---|---|---|---|
| `points` | 输入 | float32 | `[V,16,200,5]` |
| `mask` | 输入 | bool | `[V,16,200]` |
| `pose` | 输出 | float32 | `[V,16,1,17,3]` |

V为本次有效人数，只有此维动态；其他维度需以实际ONNX元数据确认。V=0时跳过模型调用。

输入五列固定为 `[x,y,z,f0,f1]`，tag不进入模型。六列预处理数组必须重新打包成连续五列缓冲区，不能直接将六列首地址作为五列张量传入，否则点与点之间的步长错误。

连续布局的元素偏移为：

```text
points[v,t,n,c]：(((v*T+t)*M+n)*5+c)
mask[v,t,n]：((v*T+t)*M+n)
pose[v,t,0,j,d]：(((v*T+t)*17+j)*3+d)
```

mask按后端bool张量接口创建，不能将float或int32缓冲区指针直接解释成bool。即使mask全真，也需按模型接口传入。

参考推理使用FP32。不要因为训练曾使用混合精度就自动改为BF16/FP16。部署后端、Execution Provider及精度应记录在验收信息中。

模型输出的是整个窗口；模型内部使用窗口内时间编号1～T，并非绝对时间戳。不能用逐帧独立调用或前帧隐状态替代完整窗口调用。

## 8. 输出坐标还原与末帧选择

对每个人、每个时间位置的17个关节：

```text
poseAbsolute[v,t,j] = pose[v,t,0,j] + center[personId,t]
```

未中心化时中心为零。若模型使用low坐标系，再执行：

```text
poseHigh = R_hlᵀ × (poseAbsoluteLow - t_hl)
```

随后仅取时间位置T−1，写入窗口末帧：

```text
frameIndex = s+T-1
rawPose = poseHigh[:,T-1,:,:]
rawIds = 本次有效人员的原ID
```

raw骨架统一为**high坐标、米、17关节**。不要取窗口中心帧，也不要平均多个窗口对同一帧的预测。不额外减髋中心、缩放骨长或把骨架移动到框中心。

模型没有置信度输出。某人无有效窗口时输出空集合，不用全零骨架冒充预测。

## 9. 时序后处理

若需复现最终显示结果，raw之后还需执行本节。算法按人保存状态，在当前raw、上次可信骨架和不输出之间选择，不做平均平滑。

### 9.1 姿态变化量与阈值

对骨架A、B：

```text
rA = (A[11]+A[12])/2，rB同理
root = norm(rA-rB)
shape = mean_j norm((A[j]-rA)-(B[j]-rB))
vA = A[0]-(A[15]+A[16])/2，vB同理
q = norm(vA)*norm(vB)
angle = acos(clamp(dot(vA,vB)/q,-1,1))*180/pi
若q<=1e-10，angle=180度
```

| 判定 | root | shape | angle |
|---|---|---|---|
| 普通变化normal | ≤2.0×dt | ≤1.25×dt | ≤60° |
| 相邻候选稳定stable | ≤1.0×dt | ≤(2.0/3.0)×dt | ≤30° |

三个条件必须同时满足。root、shape单位为米，dt为秒；angle不乘dt。

```text
weak = (D<10) 或 (N<20)
```

计数缺失按0处理。强观测即使姿态跳变也直接接受，不额外拦截。

### 9.2 每人状态与处理伪代码

状态包括最近处理帧号last、时间time、可信骨架ref、未确认异常帧pending、稳定候选段candidate。输出缓存按“帧号、人员ID”保存骨架与状态。

```text
按完整帧序列依次处理；对本帧每个有raw的人员：
    若raw含NaN/Inf：本帧不输出，也不更新状态
    若无状态或last不是前一帧：
        ref=空，pending=[]，candidate=[]，time=当前时间-0.12
    dt=当前时间-time；若dt<=0则报错
    normal = ref存在且raw与ref满足普通变化阈值

    若非weak 或 normal：
        本帧输出raw，状态accepted；ref=raw副本
        清空pending和candidate（不修改此前已输出的held）
    否则：
        将当前帧加入pending
        若candidate末项是前一帧，且当前raw与末项raw满足stable：
            追加当前raw到candidate
        否则：candidate重新从当前帧开始（不清空pending）

        若candidate长度>=3：
            将最后3项各自的raw写回各自帧，状态confirmed
            ref=当前raw副本；清空pending和candidate
        否则：
            若ref存在且pending长度<=2：
                本帧复制ref，状态held
            若pending长度>2：
                删除整个pending段该人的暂存输出

    last=当前帧号，time=当前时间
```

确认分支优先于撤销分支。confirmed是三帧各自的raw，不是平均骨架；held完整复制ref，不外推位置。

dt是相邻已处理raw的时间差，不是距离ref建立时刻的累计时间。没有raw的帧仍占位置；下一次出现时重置连续状态。整段结束没有额外确认或撤销，尾部一两帧held可保留。

对有raw但最终无输出的人记为excluded；无raw帧不伪造该人的结果。多人状态独立，修改历史时不能删除同帧其他人。

## 10. Qt执行与显示约定

推荐离线一致性流程：

```text
加载ONNX和配套参数
→ 原始帧清理与同步骨架
→ 每帧单独统计D/N
→ 全段点云积累
→ 逐个滑窗按人裁剪、采样、筛选完整窗口
→ 打包points和mask并调用ONNX
→ 加回中心、转回high、保存末帧raw及原ID
→ 对整段raw执行时序后处理
→ 发布最终缓存，UI只读播放
```

滑块回看或重复刷新不能再次推进推理和后处理。换组或换数据源时清空历史与状态。

在线显示若要保持同样的最终结果，应支持前两帧回填/删除，或按当前3帧确认、2帧保持规则延迟两帧发布并处理停止时的尾部。零延迟且禁止历史修订无法复现此离线算法。

显示需要low坐标时，对最终high骨架再做一次high→low。不要对已经是low的坐标重复转换。

如需复现参考验收区域，按**参考骨架的髋中心**在low坐标下筛人：

```text
((x-2.0)/1.6)^2 + (y/2.4)^2 <= 1
```

椭圆不参与模型裁剪或时序后处理。改用预测髋中心筛选属于另一种显示口径。

## 11. 最小验收清单

先用相同输入对齐模型接口，再对齐整条流程。交付参考数据至少包含：有序原始帧与骨架/ID、外参、采样后的points/mask、中心与ID映射、ONNX输出、还原后的raw及最终状态。

| 检查项 | 必须确认 |
|---|---|
| 模型与参数 | ONNX哈希、接口名称/类型/尺寸、T/M/H、坐标系、中心化一致 |
| 预处理 | 积累帧范围、点序、bbox、裁剪mask、D/N、采样索引一致 |
| ONNX接口 | 连续五列float32与bool mask；Python和Qt使用同一输入 |
| 数值输出 | 比较ONNX输出及还原后的raw，记录最大坐标误差和平均关节误差 |
| 人员及时序 | 原ID映射、首个输出帧、无效窗口处理一致 |
| 后处理 | 同一raw下保留ID、状态、回填与撤销完全一致 |
| 播放 | 重复显示不改变缓存和后续结果 |

必须覆盖：

- 序列少于16帧、等于16帧；窗口左端仍带入窗口外历史。
- 框内9、10、199、200、201点；验证门槛和重复/截断采样。
- 原始空帧但积累足够；某人中途无效而其他人仍有效。
- 仅ID 1、3有效；输出不能变成ID 0、1。
- high/low、启用/关闭中心化；验证逆变换只做一次。
- 两框重叠、边界点；确认重复归属和闭区间条件。
- 后处理三帧稳定回填、持续异常撤销、尾部held和缺人重置。

已有导出测试使用逐元素 `rtol=1e-4, atol=1e-4` 对比ONNX与导出参考模型。此容差不是整条部署流程的毫米级误差保证；实际Qt后端需通过真实样本验收。若Python与Qt运行同一ONNX一致，但与原始模型不同，再由模型交付方检查导出等价性，Qt无需重写图内算子。

本文未执行Qt程序或核验实际交付ONNX文件；接口尺寸与数值一致性以交付模型元数据和上述验收结果为准。
